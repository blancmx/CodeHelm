# V02-006 极限负载取消修复与复验

执行日期：2026-09-09。阶段仍在验收中，本文不宣称安装、升级或发布通过。

## 1. 发现与修复

扩大到 50,000 文件后，原生文件边界准备可能超过 10 秒；此前工作区取消需要等待该阶段完成。新增共享 Int32 取消标记，原生遍历逐项检查，取消后由既有 RAII 释放已打开句柄。分析任务取消/关闭及工作区取消都可通知边界。没有提高预算，也没有移除文件身份、链接和根目录检查。

原生测试覆盖预先取消、跨 Worker 取消、取消参数校验、句柄释放（文件可写、目录可改名）及再次锁定。原生 **7 项通过**，任务生命周期 **20 项通过**，完整类型及 lint 检查通过。

修复后的目录包在 `test-results/v02-006-cancel-package`，原候选包保留。ASAR 检查通过（66 项）。这个包来自当前工作区，仍包含保留在本地的界面改动，不是最终冻结源码重建包。

## 2. 扫描极限负载

各组 10 次；计时从渲染端调用取消 IPC 至确认任务终态，不包括点击派发。P95 采用 nearest-rank，在 10 个样本中等于最大值。

| 场景 | P95 / 最大耗时 |
|---|---|
| 普通目录扫描中 | 26.8 ms |
| 四层目录扫描中 | 24.0 ms |
| 权限异常边界准备 | 25.1 ms |
| 50,000 文件扫描中 | 682.0 ms |
| 50,000 文件边界准备 | 23.9 ms |

50 次均低于 2 秒。默认预算下恰好 50,000 个文件扫描成功；增加为 50,001 后明确失败，之前成功工作区记录保持不变。仍保留 1,000 文件预算、实际读取拒绝与取消后重扫检查。权限异常取消发生在边界准备阶段，不表述为扫描中取消。完整试验约 1.8 分钟，通过。

证据：[原始采样与边界详情](../../test-results/v02-006-scan-limit-benchmarks/desktop-scan.benchmark.ts--301f0--isolated-packaged-Electron/scan-performance.json)、[测试报告](../../test-results/v02-006-scan-limit-results.json)。复现：设置修复包的 `CODEHELM_E2E_EXECUTABLE` 和 `CODEHELM_E2E_SCAN_LIMIT=1`，运行 `pnpm.cmd exec playwright test --config=playwright.scan-performance.config.ts`。普通与极限输出分开保存。

## 5. 桌面全量回归与持续日志

修复包首次全量回归 **16 项通过、持续日志试验 1 项失败**。原始报告保留在 `test-results/v02-006-cancel-e2e-results.json`。停止计时为 2,778 ms，输入 P95 约 1,978 ms；检查发现停止计时包含路由切换，双帧输入计时受到后台帧节流影响，且把包含多行的日志事件错当成单行计数，不能作为前台交互和真实行速率的最终数据。

最终定向复测已通过（10.1 分钟）：实际接收 **1,000.013 行/秒**，输入 P95 **24 ms**，停止至会话归零 **692.4 ms**，工作集稳态变化 **-0.45%**。测试窗口显式关闭后台及遮挡节流、显示并聚焦窗口，以测量前台交互；产品默认节流行为没有更改。计时从实际 DOM 点击开始，以固定 20 ms 间隔检查终态；按换行数及 UTF-8 字节计量接收日志，发送夹具补偿定时器漂移并遵守 stdout 背压。

入口为 `playwright.candidate.config.ts`，设置修复包路径、`CODEHELM_E2E_SCOPE=sustained` 和 `CODEHELM_E2E_PERFORMANCE=1`，筛选 `measures sustained`。证据：[最终报告](../../test-results/v02-006-foreground-log-results.json)、[完整采样](../../test-results/v02-006-foreground-log-artifacts/desktop-lifecycle-measures-abfd9-log-memory-and-stop-latency/performance.json)、[停止后的窗口](../../test-results/v02-006-foreground-log-artifacts/desktop-lifecycle-measures-abfd9-log-memory-and-stop-latency/performance-stopped.png)。截图已检查，受管项目为空且显示停止成功。`performance-progress.json` 是中间采样，不作为完成凭证。

本次结论为首次全量中 16 项通过，加修正计量后的持续日志单项通过；没有改写首次失败报告，也不声称一次全量运行 17 项全过。最终类型检查、lint 均通过。[候选证据清单](../../test-results/v02-006-cancel-evidence.json) 记录 104 个文件哈希和六份明确指定的报告，保留首次失败状态，`releaseReady=false`。这些本地证据不自动进入 Git。

## 6. 环境及剩余边界

日志计量后续诊断补充：第二轮完整十分钟实测接收 **999.98 行/秒**、停止 **905.7 ms**、内存变化 **-6.87%**，但双帧输入 P95 仍为 **1,980.7 ms**，因此该轮仍标记失败。仅设置 `setBackgroundThrottling(false)` 不足以控制 Windows 遮挡帧节流。加入仅测试使用的 Chromium 后台/遮挡节流开关并显示聚焦窗口后，一分钟带负载诊断输入 P95 **29.6 ms**；该短测明确 `acceptanceRun=false`，停止 **1,080.9 ms**，不能当成十分钟验收通过。原默认终态轮询间隔会带来数百毫秒计时误差，改为固定 20 ms 后执行第三轮完整试验，结果写入 `test-results/v02-006-foreground-log-*`。产品默认节流行为及 1 秒停止目标均未更改。

远端工作流新增手动 `performance` 开关，默认关闭；开启时在同一候选包上执行极限扫描、扩展诊断/搜索、总览组合筛选及十分钟日志试验。每条命令检查退出码，不通过就终止后续测试，证据上传仍执行。候选证据格式升级为 2，接收显式报告路径列表并逐份记录状态/统计/哈希；报告缺失、空测试或有失败不会登记为通过。原始全量失败报告与后续定向复验必须一起阅读，不能把定向单项报告当成全量通过。
