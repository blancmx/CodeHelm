> 日期：2026-09-08
> 范围：Windows 本地开发版；对应开发规划第 4.4 节。
> 状态：已完成本地开发版阶段验收；安装版与发布验收另行进行。

## 1. 交付行为

运行中心的历史记录支持项目、方案名称、服务名称、状态和启动时间范围筛选。历史按启动时间与会话 ID 倒序分页，界面每页 20 条。展开记录可以查看启动/结束时间、退出码、服务错误，以及启动时保留的方案摘要。停止后的旧记录不提供进程控制；删除原方案后仍可打开历史及其日志。缺失的退出码、结束时间保持“未知”，不会补成成功。

每个会话和服务均有历史日志入口。日志从持久化文件读取，可按服务、stdout/stderr/system、关键词和日志时间范围筛选。启动时间筛选属于运行记录；日志时间筛选属于日志内容，两者分别生效。查询显示快照时间、本页实际时间范围、保留策略、扫描量、缺失文件、无效记录、截断数量和应用写盘丢弃计数。

实时控制台支持暂停跟随、回到最新、输出流与关键词筛选。暂停时冻结已加载内容，切换服务保留筛选和阅读位置。虚拟列表按像素位置回到顶部，避免超长日志行重新测量时把视口移到行尾。

导出按钮分别明确为“导出已加载日志”和“导出本页已加载日志”。导出文件包含范围说明、实际应用的筛选条件及结构化日志；尚未点击查询的新筛选不会被错误写成当前结果的范围。任何已加载导出均不宣称包含完整会话。

## 3. 资源与覆盖范围

| 对象 | 本阶段限制 |
|---|---|
| 运行历史 | API 每页最多 50 条；界面每页 20 条 |
| 单条历史详情 | 最多返回 200 个服务；超过时显示总数及截断提示 |
| 实时日志缓冲 | 沿用 5,000 条 / 4 MiB 双重上限，单条消息 64 KiB；虚拟列表只挂载可见行 |
| 待写盘队列 | 沿用 4 MiB / 10,000 条限制；过载计数在查询结果中展示 |
| 日志文件枚举 | 每个项目最多检查 512 个目录项；达到上限提示未覆盖全部文件 |
| 原生根边界 | 日志根树最多 4,096 个条目；建立失败时拒绝此次查询 |
| 单页文件读取 | 单文件最多 16 MiB，每页实际成功读取总量最多 32 MiB；余额不足时从下一页继续 |
| 单页输出 | 最多 200 条，记录 JSON 累计大小最多 1 MiB；不包括数组分隔符及响应元数据 |
| 日志读取 Worker | V8 old-generation 上限 128 MiB；这不是整个进程 RSS 上限 |
| 查询并发 | 每个窗口最多 1 个、应用最多 2 个读取请求 |
| 服务端日志游标 | 最多保留 20 个，5 分钟过期；绑定窗口与筛选条件，一次消费 |
| 界面历史日志缓存 | 最多保留最近 10 页；翻阅被淘汰的早期页需重新查询 |
| 阅读位置缓存 | 最多保留 100 个项目/服务组合；仅本次控制台挂载期间有效 |

读取开始前等待有界写盘队列并建立原生文件边界，随后交给独立 Worker。请求启动 8 秒后发出取消信号，读取 Worker 可终止；准备和边界清理仍需完成，因此不将 8 秒描述为整个 IPC 的硬性返回时限。

分页固定第一次查询时的文件集合和文件长度。新追加内容需重新查询；跨页文件发生删除、替换或截断时计入缺失，而不是返回伪造的完整结果。日志按文件名顺序分页，不承诺多个服务文件全局按时间合并。

当前保留策略不能证明历史上从未丢失日志。文件清理、轮转、未落盘或异常记录均可能造成缺口；一个空结果页后仍可能有下一页。写盘丢弃为本次应用累计值，界面缓冲淘汰为本次界面累计值，均不伪装成单会话精确损失数。

## 4. 验收证据

### 数据与文件测试

- 65 条历史记录跨页无重复或遗漏；相同启动时间使用 ID 继续排序。组合筛选、已删除方案、未知退出码和参数化查询均有覆盖。
- 450 条持久化日志分页为 200/200/50，验证服务、输出流、关键词和时间筛选，导出逐条等于当前结果。
- 真正删除轮转文件后继续分页，结果报告缺失；异常 JSON、其他会话记录及非法项目路径不会混入结果。
- 大消息分页遵守输出预算；查询后追加的记录不进入已有快照。
- 超过 16 MiB 的文件报告不可读；三个 12 MiB 文件按 24 MiB、12 MiB 分两页读取，验证总读取预算。
- 原生测试验证共享日志读取允许追加与重命名，仍持有原文件句柄；硬链接拒绝、路径边界及原有执行读取边界回归通过。

### 实际 Electron

采用最终构建产物、真实 Electron 窗口和临时用户数据目录。测试创建受管 fixture 进程，不使用正式用户数据库。

1. fixture 向 stderr 分段输出环境密钥并以退出码 7 失败；删除方案、关闭并重启应用后仍能找到失败记录。
2. 从历史界面打开该服务日志，筛选 stderr 与关键词，界面仅显示匹配内容；实际下载的导出文件含 `[REDACTED]`，不含密钥原文或普通 stdout。
3. 高频日志场景下暂停跟随、切换服务恢复滚动位置、保留关键词及输出流筛选，再回到最新。
4. 历史日志读取与停止会话同时进行，停止请求在测试阈值 5 秒内完成；日志返回不超过 200 条，受管会话全部退出。
5. 既有环境诊断、工作区复扫、多方案、执行确认、重启和固定端口复核共同回归。
