## 5. 性能口径与未覆盖项

持续日志采样使用 `app.getAppMetrics()` 中各 Electron 进程的工作集之和。它是本机应用进程的内存指标，不包括受管项目进程，也不是跨平台严格 RSS；共享页面可能在多个进程中重复计入。比较相同口径的 120～180 秒与最后一分钟中位数，并记录绝对峰值，阈值为增长不超过 20%。停止耗时从点击运行中心停止按钮开始，直至受管会话数归零，目标不超过 1 秒。

本轮持续测试结果：120 次采样；前稳态中位数 533.83 MiB，最后一分钟中位数 523.38 MiB，变化 **-1.96%**，峰值 **548.05 MiB**；点击停止至会话归零 **924 ms**，两项阈值均通过。测试机为 Windows 构建 `10.0.26200`、AMD Ryzen 9 7940HX、可见物理内存 16,340,414,464 字节；Node 24.16.0、Electron 44.0.0、electron-builder 26.15.3。

原始证据：[性能采样 JSON](../../test-results/packaged-e2e-artifacts/desktop-lifecycle-measures-abfd9-log-memory-and-stop-latency/performance.json)、[停止后的实际窗口](../../test-results/packaged-e2e-artifacts/desktop-lifecycle-measures-abfd9-log-memory-and-stop-latency/performance-stopped.png)、[v0.1 schema 升级窗口](../../test-results/packaged-e2e-artifacts/desktop-lifecycle-migrates-0ea7b-usable-pre-upgrade-snapshot/upgrade-v010.png)。已检查这些实际窗口截图。

完整打包版结果：[17 项测试报告](../../test-results/packaged-e2e-results.json)。候选清单：[目录包](../../test-results/v02-006-evidence.json)、[安装器](../../test-results/v02-006-installer-evidence.json)。这些本地产物需在下一次运行前归档，不自动进入 Git 或公开发布。

本轮是开发工作站测量，期间存在构建/文件校验等其他工作，不能代替专用空闲测试机上的发布基准。目标负载由 fixture 定时器产生，实际吞吐可能受调度和输出背压影响。

### 5.1 千项目搜索、诊断与热启动补测

2026-09-08 后续补测使用同一个隔离目录包和临时 SQLite，写入 1,000 个项目。保留用户当前开发窗口，不改其数据；一次预热及首次 schema 迁移不计入热启动样本。

| 场景 | 样本与测量口径 | 结果 |
|---|---|---|
| 千项目快速搜索 | 30 个不同精确名称；从真实 input 事件至匹配结果可见，再等待两个动画帧 | P95 **19.50 ms**，低于 200 ms |
| 本地 Node 方案诊断 | 30 次真实 IPC；检查返回项非空、没有 blocked，且没有活动会话 | P95 **8.62 ms**，低于 5 秒 |
| 当前候选热启动 | 10 次关闭重开；从启动到总览标题可见且 IPC 返回 1,000 项目 | 中位数 **756.05 ms**，P95 **805.64 ms** |

启动中位数使用偶数样本中间两项的平均值，P95 使用 nearest-rank。搜索样本是在快速搜索弹窗中筛选到单个项目，不代表总览的所有组合筛选或大量匹配结果；诊断只有一个本地 Node 方案，不代表所有语言、磁盘和异常环境。热启动没有清除 OS 缓存，也没有 v0.1 二进制对照，因此不宣称启动回退比例达标。

入口：[独立性能套件](../../e2e/desktop-performance.benchmark.ts)、[独立配置](../../playwright.performance.config.ts)。命令：`pnpm.cmd exec playwright test --config=playwright.performance.config.ts`。默认使用本轮隔离目录包，也可通过 `CODEHELM_E2E_EXECUTABLE` 指定其他测试二进制。结果目录与之前的 17 项回归完全分开。

### 5.2 扫描取消与预算补测

2026-09-09 使用现有隔离目录包、新建临时用户数据及真实 Windows 文件权限运行补测。普通样本为 1,201 个目录；深层样本为 300 组四层目录，共 1,201 个目录。权限样本只对临时目录中的一个文件添加读取拒绝，先确认读取返回 EPERM/EACCES，结束后移除该拒绝并清理夹具。

| 场景 | 取消时机 | 次数 | P95 / 最大值 |
|---|---|---|---|
| 普通目录 | 收到实际扫描进度后 | 10 | 15.4 / 15.4 ms |
| 四层目录 | 收到实际扫描进度后 | 10 | 13.7 / 13.7 ms |
| 读取权限异常 | 原生文件边界准备阶段 | 10 | 16.9 / 16.9 ms |

计时从渲染端调用取消 IPC 开始，直到取消响应及任务终态查询完成；不包含鼠标点击派发。三类样本均确认 `cancelled`，全部低于 2 秒。权限异常发生在原生边界建立阶段，因此其取消结果不能表述为“已进入扫描后的权限异常取消”。未取消的权限样本单独运行，返回 `Cannot lock project file (Win32 5)`，证明没有静默忽略读取拒绝。

预算样本有 1,001 个文件（包含清单）：默认 50,000 预算时扫描成功；降至 1,000 后返回 `Project file count exceeds security lock limit`，此前保存的工作区记录逐项相等；999 和 50,001 设置值被拒绝。恢复默认预算后可再次成功扫描。取消任务不写入成功工作区记录。本轮没有创建 50,000 文件极限负载，也不覆盖物理磁盘故障。

入口：[扫描补测](../../e2e/desktop-scan.benchmark.ts)、[独立配置](../../playwright.scan-performance.config.ts)。命令：`pnpm.cmd exec playwright test --config=playwright.scan-performance.config.ts`。原有搜索/诊断/热启动配置改为精确匹配自己的文件，避免两个套件相互覆盖证据目录。

结果：[30 次原始采样及失败详情](../../test-results/v02-006-scan-benchmarks/desktop-scan.benchmark.ts--301f0--isolated-packaged-Electron/scan-performance.json)、[扫描测试报告](../../test-results/v02-006-scan-results.json)。补测通过（9.5 秒），`tsc -p tsconfig.e2e.json` 和 lint 通过。当前代码仅新增测试基础设施，未重新构建候选包，因此这组数据属于已有本地二进制，不宣称是冻结提交重建包的发布证据。
