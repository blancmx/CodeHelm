# V02-002 工作区复扫与分析差异

更新日期：2026-09-08。基线为已推送的 V02-001 提交 `cd97b6136dd55a979f662b102f5fce9c782e418e`。本阶段实现本地工作区复扫、分析差异预览和明确应用建议；范围依据 [开发规划第 4.2 节](./01-v0.2开发规划与验收方案.md)。

## 1. 用户入口与行为

### 工作区复扫

项目总览 → 导入项目 → 工作区批量导入 → 打开工作区复扫记录。

选择工作区目录，设置扫描深度和排除目录名，点击“保存设置并复扫”。保存后的工作区可以从下拉框再次选择。排除规则按目录名精确匹配，用逗号分隔；候选项目的“忽略此候选”影响批量导入选择，在下次复扫时保存。

结果使用文字区分新增、已纳管、变化、路径不可用、无法判断。变化项目显示“分析可能过期”及涉及的相对文件名，可进入项目重新分析。复扫只更新本地记录，不执行命令、安装依赖、删除项目或修改源码。

批量导入显示成功、已纳管跳过、失败数量和逐项原因。失败后可以只重试失败项目。已建立记录但分析失败的项目沿用同一记录重试，不重复建立项目。导入结束后立即刷新纳管状态。

### 分析差异

项目详情 → 重新分析 → 关闭分析完成窗口 → 启动配置 → 查看分析差异。

首次导入仍可自动建立默认检测方案。此后重新分析只保存新的分析快照，不自动更新已有运行方案。预览比较最近两次成功分析中的模块、技术栈及建议命令，包含命令的来源和脚本内容；即使命令仍是 `npm run start`，脚本内容变化也能出现在差异中。

用户点击“确认应用分析建议”后，才更新默认检测方案。人工服务和已有环境变量保留；不再匹配检测结果但携带环境变量的旧服务也保留。未手动编辑的检测服务按新建议合并，可能涉及新增服务、命令、端口或依赖。现有进程继续使用启动时快照，不会因应用分析建议自动重启。

不存在默认检测方案时，不修改用户自行创建的方案。当前编辑尚未保存时不能应用；预览绑定窗口、项目、当前分析及全部已存方案，一分钟有效，一次消费。配置或分析变化、过期、其他窗口提交都会被拒绝，异步准备结束后再次校验。

## 2. 实现与数据兼容

| 范围 | 实现 |
| --- | --- |
| 持久化 | 复用现有 `app_settings` 的独立 `workspace-v02:` 键，按规范化根路径摘要区分工作区；不改变全局设置值，不增加数据库 schema 版本 |
| 保存内容 | 根目录、扫描深度、目录排除规则、忽略候选、最近完整成功时间、最近检查结果、成功输入摘要及待分析变化 |
| 扫描执行 | 复用已有独立 Worker、任务 ID、进度、取消和退出清理；取消后等待任务释放，再允许立即重扫 |
| 比较依据 | 对指定关键文件计算 SHA-256；不以 mtime/size 相同断言内容未变化，不引入文件级缓存 |
| 规则失效 | 扫描深度、排除目录和清单规则版本参与比较基线；改变范围后建立新基线，不把排除的内容误报为删除 |
| 部分失败 | 保留完整成功基线；可读区域仍可展示，相关候选显示无法判断；旧的待分析变化单独保留 |
| 历史候选 | 未再次发现的旧候选不会自动移除，区分目录缺失、存在但已无清单、未覆盖和无法判断 |
| 分析保存 | 已有方案不再自动合并；成功快照保存与项目分析时间更新在事务内完成；失败或取消不替换成功快照 |
| 读取和解析失败 | 桌面严格模式拒绝部分读取失败和探测器抛错；主要 JSON/TOML/POM 清单及 pnpm 工作区 YAML 先验证，防止宽松解析器吞错后保存为成功 |

待分析变化在重复复扫或临时权限失败后继续保留。项目成功重新分析后，下一次完整可比较复扫可清除旧提醒。它仍是“可能过期”的提示，不证明分析与整个文件系统处于同一原子快照。

## 3. 支持范围与限制

- 扫描深度 0～4，默认 2；隐藏目录、依赖和构建目录沿用既有跳过规则，新增最多 50 个排除目录名。支持在深度范围内继续发现嵌套 Monorepo 项目。
- 单次最多发现 500 项，每个目录最多枚举 2,000 个条目，最多检查 2,000 个目录；达到截断边界不作为完整成功基线。最多保存 50 个工作区，历史候选保留上限 1,000。
- 批量导入每次最多 100 项；忽略候选最多 500 项。界面按当前未忽略、未纳管候选选取前 100 项，已有记录由主进程再次去重。
- 摘要清单覆盖 `.gitignore`、Node 清单/锁文件、pnpm workspace、lerna/nx/turbo、Python 标准清单和锁文件、Maven/Gradle 的列出文件、Cargo、Go 及 `index.html`。完整列表在 `workspace-inventory.ts` 的 `WORKSPACE_INPUTS`。
- 每个摘要文件最多 2 MiB，一次摘要读取预算 32 MiB；超过限制记为无法判断。只保存相对文件名和摘要，不保存原始文件内容，不对 `.env` 或普通源码计算本阶段摘要。
- `.gitignore` 的内容变化会触发提示；工作区发现本身使用目录排除规则，不解释每个项目的全部 gitignore 语义。项目完整分析继续沿用既有 `.gitignore` 处理。
- 变化归属于候选目录及其已扫描子目录；不推断父工作区锁文件对每个子项目的完整依赖传播。深度外变化、任意源码变化、动态构建配置和未列入清单的文件均不在此比较范围。
- 原生路径边界拒绝链接越界；目录 junction 跳过并记为问题。根路径无法取得安全边界时整个任务失败，旧结果保留；不宣称所有 Windows ACL 组合都能部分成功。
- 解析验证针对明确支持的清单格式，不执行 Gradle、Maven wrapper、Python 构建后端或项目脚本来获取动态配置。清单语法可解析不等于构建语义完整有效。
- 分析差异比较最近两次成功快照，不是与每一个自定义方案逐字段对比；默认检测方案的明确应用只覆盖本阶段边界，多方案管理与更完整的变更保护属于 V02-003。

## 4. 验收矩阵

| 场景 | 结果与证据 |
| --- | --- |
| 新增/删除清单 | 隔离真实目录的摘要测试覆盖文件增删；历史候选不因发现结果缺失自动删除 |
| 同大小内容变化 | 相同长度 JSON 修改产生不同摘要；按文件名显示变化 |
| 排除规则改变 | 持久化测试验证新规则建立独立基线；桌面测试验证 archive 排除与 ignored 候选跳过 |
| 嵌套 Monorepo | 真实中文和空格目录中的嵌套 app 可被发现，排除目录不进入结果 |
| 链接越界 | 真实 junction 跳过且报告问题；沿用原生根边界保护 |
| 部分目录无权限 | 测试在单个目录的 opendir 注入 EACCES，其余真实目录仍可发现；不作为真实系统 ACL 全组合验收 |
| 取消后立即重扫 | 既有 Worker 集成测试验证终止、释放任务占用及再次扫描成功，本轮全量重跑通过 |
| 部分失败保留成功基线 | 持久化测试覆盖完整→部分→完整；待分析提醒跨临时失败保留，分析成功后可清除 |
| 明确应用建议 | 单元测试覆盖无写入预览、一次性 token、不同窗口、过期、并发编辑拒绝，以及人工命令和环境变量保留 |
| 真实桌面完整流程 | 复扫发现 package.json 变化→重新分析→已有方案完全不变→预览 start/dev 及来源差异→确认后方案更新 |
| 清单损坏 | Electron 修改清单为无效 JSON，分析失败，最后成功快照 ID 不变；无活动服务会话 |
| 重启与重试 | 关闭并重开真实 Electron 后工作区记录一致；批量导入一成功一失败，修复后仅重试失败项，最终项目数量仍为 2 |
