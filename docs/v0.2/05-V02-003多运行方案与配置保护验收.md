# V02-003 多运行方案与配置变更保护

日期：2026-09-08。状态：已完成本地开发版阶段验收。范围：CodeHelm v0.2 的第三个 P0 开发阶段。

本阶段基于当前工作区中的 V02-001、V02-002 实现继续开发。未提交、推送或发布安装包；原有界面改动和 V02-002 工作保留。v0.1 仍在进行的门禁不纳入本阶段。

## 1. 用户行为与交付范围

| 操作 | 本阶段行为 |
|---|---|
| 管理运行方案 | 项目详情顶部选择方案，支持新建、复制、删除；名称与默认设置在启动配置页修改后保存 |
| 切换方案 | 服务控制、启动配置、环境诊断及启动动作使用当前选择；有未保存修改时，先保存或明确放弃后再切换 |
| 设置默认 | 同项目最多一个默认方案；事务内撤销其他默认标记。删除默认方案时，从剩余方案中选定一个默认方案 |
| 复制 | 复制已保存配置，生成新的方案和服务标识，重映射内部依赖；副本独立修改，不继承原方案执行授权 |
| 编辑服务 | 支持启用组合、命令、参数、工作目录、环境变量、依赖、已有 TCP/HTTP 就绪检查和失败处理策略 |
| 校验依赖 | 保存前显示重复标识、缺失依赖、启用服务依赖停用服务、循环依赖；主进程重复校验，拒绝非法保存 |
| 编辑运行中方案 | 显示“下次启动生效”；服务控制页继续展示启动时的会话配置，不将新命令误显示为正在执行的命令 |
| 删除方案 | 有活动会话、等待确认/执行的请求或待核验进程时拒绝删除，提示先停止或取消；删除后历史名称和服务记录保留 |
| 单服务重启 | 主进程确认窗口展示原会话的实际命令和影响范围；取消不停止旧服务，确认后只重启选中的受管服务 |

服务编辑器中原有 `database` / `custom` 分类与契约不匹配的问题同步修复，分别使用 `auxiliary` / `tool`。

## 2. 配置、建议与运行状态

1. 分析建议继续通过 V02-002 的差异预览显式应用。方案选择与复制不会触发分析或自动执行。
2. 已保存方案是下一次启动的输入。方案名称、服务选择和失败策略可以独立调整。
3. 编排器在启动入口复制输入；当前运行的配置与后续编辑分离。主进程返回用于展示的 `effectiveProfile`，其中所有环境变量值均置空。
4. 运行记录保存启动时的 `profileName` 和 `profileUpdatedAt`。完整展示配置仅保留在当前主进程内存，不新增完整命令或环境值的历史落盘。
5. 项目详情加载时重新读取主进程会话状态。仍保留既有的请求序号和状态修订检查，避免旧响应覆盖更新的进程事件。

## 3. 执行保护

沿用主进程执行确认、一次性令牌、方案及执行输入指纹机制。命令、参数、目录、依赖、环境或关键输入文件改变后，旧授权不能启动新的执行内容。复制方案使用不同方案 ID，因此不能借用原方案授权。

单服务重启增加独立确认：

- 从受管进程中读取原会话的服务配置和根目录，列出直接依赖该服务的服务名称，提示可能短暂不可用；不默认级联重启。
- 确认前检查所属会话及依赖状态；确认后、旧进程停止后的检查阶段再次确认依赖就绪及执行文件指纹。
- 依赖不处于 `RUNNING`、会话正在停止、旧服务已有替代实例等情况拒绝重启。
- 等待重启确认同样占用方案的删除保护。关闭窗口、导航或取消确认不创建替代进程。
- 若旧进程已经停止后环境检查失败，则保留明确失败原因，不假称恢复成功。修复后可重新启动方案。

## 4. 数据兼容

数据库 schema 从 2 升至 3，仍由既有受保护启动流程执行迁移。

| 数据项 | 用途 |
|---|---|
| `run_profiles.deleted_at` | 逻辑删除标记，正常列表、读取和执行路径不返回已删除方案 |
| `run_sessions.profile_name` | 启动时方案名称，后续重命名不会改写 |
| `run_sessions.profile_updated_at` | 启动时配置保存时间 |
| `idx_profiles_default` | 部分唯一索引，约束同项目未删除方案最多一个默认项 |

删除清除该方案的服务配置，但保留方案关联行，避免现有级联外键删除运行历史。已删除方案不能通过再次保存相同 ID 恢复。当前不提供撤销删除入口。

旧库迁移时，历史名称以迁移当时可获得的方案名称补齐；无法追溯旧版本未记录的更早名称或配置版本。重复默认项在创建唯一索引前归一化。迁移、默认归一化及 schema 版本写入处于同一事务。

本阶段验证的是隔离 SQLite 数据库迁移和本地 Electron 行为；不代表安装版升级、回滚与备份恢复门禁已完成。
