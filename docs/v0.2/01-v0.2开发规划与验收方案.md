## 1. 版本定位与核心决策

v0.2 建议定位为“更适合日常使用的本地项目工作台”。沿用本地优先、Windows 优先、静态分析与受控执行分离的产品方向，围绕三个结果投入：

1. **更快找到并维护项目**：工作区复扫、变更提示、项目收藏与归档、失效路径修复。
2. **更容易成功启动和定位失败**：启动前环境诊断、可复用运行方案、清晰的失败原因与历史日志。
3. **更放心长期使用和升级**：可验证的备份恢复、配置迁移、真实桌面自动化与安装升级验收。

不建议在 v0.2 同时引入云同步、完整 Git 客户端、AI 自动修复、Docker 编排和多平台正式发布。它们改变执行边界或交付矩阵，容易挤占核心体验与数据可靠性的投入。

本文优先级为建议的版本裁剪规则，不是已经批准的排期：

- **P0：v0.2 必交付**，发布前必须达到对应验收要求。
- **P1：按容量纳入**，在 P0 稳定且风险明确后逐项冻结；未纳入的功能不可宣传为 v0.2 已支持。
- **P2：后续候选**，本版本只保留方向，不进入实现关键路径。

## 4. P0 详细需求

### 4.1 V02-001：启动前环境诊断与失败指引

**用户场景**：导入项目后，不必先试运行一遍才发现运行时缺失、工作目录失效或端口冲突。

**需求**：

1. 在项目详情提供“检查运行环境”，启动前复用同一套检查结果模型。
2. 检查工作目录、配置引用文件、可执行文件来源、运行时版本约束、包管理器与锁文件一致性、必需环境变量是否填写、端口冲突。
3. Node.js/Web、Python、Java 为首批完整验收范围。Go、Rust 保留既有能力；未覆盖的诊断显示“不支持此项检查”，不能显示通过。
4. 每项返回 `通过 / 警告 / 阻断 / 未知 / 不适用`，并附检查时间、依据和建议动作。
5. `node_modules` 或 `.venv` 存在只作为线索，不宣称依赖完整或版本兼容。
6. 诊断结果与方案版本、环境摘要绑定；配置变化后结果过期，启动时重检关键项。
7. 缺依赖时给出安装计划预览；复用既有受控安装流程。安装成功后重新诊断，不把下载完成等同于可启动。
8. 统一常见错误：命令不存在、版本不兼容、缺少变量、端口占用、就绪超时、提前退出。保留原始原因和关联会话入口。

**执行边界**：静态检查不执行项目脚本；需要调用运行时版本命令时，仅使用解析后的明确可执行文件、固定参数和超时，不自动运行仓库提供的 wrapper、包管理器 shim 或任意 shell。无法证明来源可信时返回未知，由用户选择后续动作。检查不触发包下载、依赖安装、数据库迁移或提权。

**验收**：覆盖正常环境、缺运行时、版本约束不满足、多锁文件冲突、虚拟环境失效、缺变量、端口抢占和命令超时。所有阻断项能定位到具体服务；错误不展示密钥；诊断阶段不产生 fixture 声明的脚本副作用。端口预检通过后被抢占仍能正确报告启动失败。

### 4.2 V02-002：工作区复扫与分析差异

**用户场景**：在总文件夹中新增、移动或修改项目后，能够知道哪些项目需要导入或重新分析。

**需求**：

- 保存工作区根目录、扫描深度、排除规则、最近成功扫描时间及用户忽略的候选。
- 复扫结果分为新增、已纳管、变化、路径不可用、无法判断；单个权限失败不清空其他结果。
- 手动复扫为默认入口；本版本不强制常驻递归文件监听。
- 优先监测清单、锁文件、workspace 配置等关键输入变化；显示“分析可能过期”及变化文件。
- 重新分析展示技术栈、模块和建议命令差异，由用户决定是否更新运行方案。
- 保留最近成功快照；取消、超限或局部解析失败不以不完整结果覆盖成功快照。
- 批量导入展示成功、失败、跳过数量及原因，仅对失败项重试；重复操作不重复创建项目。

**实现建议**：先完成复扫差异，再做文件级缓存。缓存键至少包含规范路径、内容摘要、分析器版本和影响结果的扫描设置；删除文件、规则修改、版本变化均触发失效。mtime/size 只能辅助筛选，不能作为正确性的唯一依据。第一阶段使用安全全量重扫也可交付，不为追求“增量”牺牲一致性。

**验收**：覆盖新增/删除清单、同大小内容变更、忽略规则变化、嵌套 Monorepo、中文与空格路径、链接越界、取消后立即重扫、部分目录无权限。人工命令和环境变量保持不变；无法扫描不误判为项目已删除；复扫不自动运行或移除项目。

### 4.3 V02-003：多运行方案与配置变更保护

**用户场景**：同一个全栈项目可在“仅前端”“完整开发”“调试”之间切换，不必反复改写默认配置。

**需求**：

1. 提供方案列表、复制、重命名、设为默认和删除；一个项目最多一个默认方案。
2. 允许选择服务组合、依赖关系、就绪检查和失败策略；保存前显示环依赖或引用不存在的服务。
3. 区分检测建议、用户配置和当前会话生效配置，正在运行的会话使用启动时的不可变快照。
4. 保存运行中方案仅影响下一次启动；显示生效时机，不暗中修改现有进程。
5. 命令、参数、工作目录、依赖、环境或关键执行输入变化后，使旧执行授权失效，继续沿用主进程确认机制。
6. 可删除方案但不能丢失关联历史的可读信息；运行中的方案禁止直接删除，先引导停止或取消操作。
7. 重启失败服务前预览实际影响范围；只重启用户选择且依赖满足的受管服务，不默认级联重启健康服务。

**验收**：同项目三套方案可切换并重启持久化；复制不共享可变配置引用；多次设默认后仍唯一；编辑不改变旧会话快照；旧确认不能授权新命令；取消确认不启动进程；删除或改名后历史仍可正确展示。

### 4.4 V02-004：运行历史与日志排障升级

**用户场景**：应用重启后仍能找到昨天启动失败的服务和对应错误，而非只能查看当前屏幕日志。

**需求**：

- 按项目、方案、服务、时间范围和状态检索会话；使用分页或游标，不一次加载全部记录。
- 会话展示开始时间、结束时间、退出码、就绪失败原因、当时方案摘要和相关日志。
- 历史未知时间、未知退出码继续显示未知，不能推算后写成真实事实。
- 日志支持暂停跟随、回到最新、stdout/stderr 筛选及关键词查询；切换服务保留筛选和滚动位置。
- 日志导出明确是“当前已加载内容”还是“指定时间范围”，不能把缓冲区部分数据标为完整日志。
- 被轮转删除或截断的内容明确提示不可用；展示保留策略和实际查询范围。
- 采用有界队列、背压、虚拟列表或分页，显示丢弃/截断数量，避免静默丢失。
- 脱敏在展示、持久化、查询和导出链路保持一致；禁止为了排障记录原始秘密。

**验收**：跨应用重启检索同一失败会话；高频日志期间可停止服务；轮转后提示缺失范围；导出内容与筛选范围一致；秘密测试值不出现在持久化和导出结果；方案删除后历史仍可打开。

### 4.5 V02-005：备份管理与受控恢复

**用户场景**：升级前能创建有效备份；出现问题时能判断哪个备份可用并在明确范围内恢复。

**需求**：

1. 设置页展示备份时间、大小、来源版本、schema 版本、校验状态和目录入口。
2. 支持手动一致性备份，明确备份范围为 CodeHelm 管理数据，默认不含项目源代码、依赖或服务日志。
3. 备份必须使用数据库支持的一致性方式，不能在线随意复制活动数据库及 WAL 当作成功备份。
4. 设置数量/容量保留策略，清理时排除正在写入、恢复所需和明确保留的备份；清理失败可见，至少保留一个经验证可用备份。
5. 恢复先对候选副本做完整性、外键、schema 兼容与可读性检查，展示将替换的数据范围。
6. 用户确认后停止本应用任务与受管会话，取得数据库独占访问，再保全当前数据并执行恢复；无法独占时拒绝继续。
7. 恢复失败保留原库、候选库和诊断信息，不进入空库初始化“伪恢复”。
8. 跨机器敏感值可能无法解密，必须标明并要求重新输入；备份文件本身不宣称无敏感信息。

**升级与回退**：迁移前备份、事务化迁移、失败保护。旧二进制不得直接打开不兼容的新 schema；回退需要旧版本及迁移前备份成对恢复，并明确会失去备份后新增的管理数据。恢复不回滚项目源码或项目服务产生的数据。

**验收**：在隔离数据中演练正常恢复、损坏候选、未来 schema、磁盘空间不足、文件锁、备份中断和迁移失败。校验项目、方案、设置与历史关键字段一致；不操作正式用户数据库；中断后重开不静默丢失数据。

### 4.6 V02-006：桌面 E2E、性能与升级交付

**需求**：

- 复用 v0.1 已建立的检查；缺失的 lint、实际 Electron E2E 和 CI 单独补齐。
- CI 使用隔离 userData、临时项目、随机测试端口和精确进程归属，失败也要清理自身资源。
- 覆盖 Renderer/Main/Preload、Worker、SQLite 原生模块及最终安装产物，不仅覆盖浏览器页面。
- 为每个候选产物记录提交、依赖锁文件、打包环境、哈希、测试报告和已知限制。
- 发布版本号在真正发布实施时更新，本次规划不修改任何 package 版本。

**Windows 验收矩阵**：全新安装、v0.1 原数据升级、重复安装、卸载重装、路径含中文/空格、普通用户权限、无开发工具环境。应用可启动与被管理项目可运行分别验收；缺少运行时的环境应正确诊断，不能要求无 Node/Python/JDK 也能运行相应项目。

**发布要求**：冻结最低 Windows 版本和架构；签名及分发渠道决策独立记录。未签名包只能按明确标识的内部试用范围交付，不能视为面向公众的可信正式安装器。干净环境和真实可见 Electron 流程为发布证据，构建成功不替代它们。

**验收**：所有 P0 流程在安装版闭环；升级保留数据且恢复演练通过；正常退出无本次受管进程遗留，身份不明确的外部进程不被终止；CI 失败不能生成“已通过”发布记录。

## 5. P1 新增与体验需求

### 5.1 V02-007：项目整理与路径修复

- 收藏、归档、标签组合筛选与最近运行排序；复用已有标签字段，避免另建重复体系。
- 归档只影响默认列表，不停止进程或删除源码；运行中项目仍在运行中心可见。
- 路径失效时允许选择新位置，核对清单和用户确认后再绑定；不能只凭同名目录自动认领。
- 重定位后重新分析、核验相对路径并使旧执行授权失效；历史仍保留旧路径摘要。
- 批量操作显示逐项结果；取消不撤销已明确完成的项目，并准确展示已完成数量。

**验收**：收藏和归档重启保持；路径冲突不能重复绑定；大小写差异和目录链接得到一致处理；移除纳管记录不删除项目文件。

### 5.2 V02-008：运行配置导入导出与模板

- 导出版本化 JSON，包含服务、依赖、就绪检查及变量名称；默认剔除秘密值、绝对机器路径、运行历史和所有执行授权。
- 导入先校验格式、大小、路径与依赖，再展示差异；绑定本地项目后保存为新方案，不静默覆盖。
- 通用模板使用显式占位符；缺失变量阻断启动。模板保存不执行安装或脚本。
- 暂不提供跨机器秘密迁移或在线模板市场。

**验收**：导出再导入结构等价；恶意路径、环依赖、超大输入与未知主版本被拒绝；默认导出无秘密测试值；导入后必须重新确认执行。

### 5.3 V02-009：本地 Git 状态摘要

- 展示当前分支、未提交文件数量、最近提交摘要；标注最近刷新时间。
- 默认按进入页面或手动刷新获取，不自动 fetch，不推送、不提交、不切换分支。
- ahead/behind 如展示，只基于本地已有远端跟踪信息，并明确可能过期。
- 支持无 Git、非仓库、worktree、detached HEAD、大仓库超时；诊断失败不影响项目启动。
- 固定只读子命令及参数，禁止项目自定义 Git 命令入口；限制配置、外部 helper 和输出体积带来的执行风险。

**验收**：刷新前后工作树内容不变、不产生网络访问；状态不支持或超时显示未知；中文路径与 worktree 结果正确。

### 5.4 V02-010：系统托盘

- 默认保持现有关闭窗口行为；用户主动开启“关闭到托盘”后才隐藏窗口并继续运行。
- 窗口关闭、隐藏、显式退出语义分别说明；首次启用提供清晰提示。
- 托盘提供显示窗口、查看运行状态和退出；退出执行受管服务停止流程。
- 暂不新增开机自动运行项目或异常重开自动接管历史进程。

**验收**：隐藏后服务继续运行；恢复窗口状态正确且无重复订阅；退出与启动竞态正确处理；明确身份不匹配的进程不会被清理。

### 5.5 V02-011：脱敏诊断包

- 用户主动选择时间和会话，预览清单后导出应用版本、错误码、诊断结果和有限日志。
- 默认排除源码、数据库原件、环境变量值、完整命令秘密及不必要绝对路径；路径使用一致化占位符。
- 明示脱敏不能保证识别日志中的所有自定义敏感文本，允许逐项排除和取消。
- 本地生成，不自动上传或发送；设置体积上限并报告缺失文件。

**验收**：在含测试秘密与用户路径的夹具中验证排除规则；取消不导出；部分文件不可读时清单准确；不存在静默网络上传。

## 8. 技术与数据设计建议

### 8.1 分层职责

- `packages/domain`：诊断结果、方案版本、差异模型与纯校验规则。
- `packages/contracts`：版本化 DTO、输入校验、分页契约、任务事件与错误码。
- `packages/database`：工作区、备份元数据、方案版本与迁移；复用现有项目/方案/会话表。
- `packages/analyzer`：变更指纹、差异、缓存失效；保持静态分析无执行副作用。
- `packages/runner`：运行前复检、配置快照、有界日志读取和受管进程控制。
- `apps/desktop/src/main`：文件与进程权限、确认授权、备份恢复协调、可信命令解析。
- `apps/desktop/src/renderer`：展示诊断与状态，不自行推断最终执行授权或进程归属。

开工时核对当前分层和接口再决定具体文件；本文不要求提前创建新包或替换已有模块。

### 8.2 建议模型增量

| 模型 | 建议增量 | 兼容要求 |
|---|---|---|
| Project | 收藏、归档时间、可选工作区关联 | 老项目默认不归档；不复用 tags 存内部状态 |
| Workspace | 根目录、设置、忽略候选、上次成功扫描 | 移除工作区不级联删除源码或项目 |
| Analysis | 输入摘要、分析器版本、差异摘要 | 保留旧成功快照；缓存可重建 |
| RunProfile | 修订号、默认唯一性 | 老方案可读；复制生成新 ID |
| RunSession | 脱敏的执行配置快照 | 历史不依赖可删除的现行配置才能展示 |
| DiagnosticResult | 方案修订、时间、检查项、状态、证据 | 有过期规则；不持久化秘密值 |
| BackupMetadata | 路径引用、大小、schema、校验状态 | 文件缺失显示失效，元数据不等于验证成功 |

若上述字段已有等价实现，则复用。新增表、字段、索引及历史外键处理在迁移设计中定稿，不在本文锁死 SQL。尤其要评估现有方案删除的级联关系，防止新增删除入口意外清空运行历史。

### 8.3 IPC 与并发要求

- 新接口使用有限能力，不提供“任意命令”“任意路径读取”通用入口。
- Main 对项目归属、路径边界、请求大小和状态二次校验。
- 诊断、复扫、备份等长任务携带 task ID、进度、取消和最终结果；过期事件不覆盖新状态。
- 同项目复扫/导入幂等；重复启动复用现有竞态保护；恢复与所有数据库写入互斥。
- 会话开始、配置保存和备份完成以实际持久化成功为准，不提前显示成功。

## 9. 验证策略与性能预算

以下为待冻结的工程目标，**不是已经测得的性能或完成率**。M0 记录同一台 Windows 测试机的 CPU、内存、磁盘、系统、构建类型、样本及冷/热缓存条件；如需调整目标，应说明依据后冻结。

| 场景 | 建议样本与目标 | 测量方法 |
|---|---|---|
| 项目列表 | 1,000 项目，筛选反馈 P95 ≤ 200ms | 固定数据重复操作至少 30 次，采集输入至界面完成时间 |
| 扫描交互 | 默认 50,000 文件预算内，取消后 ≤ 2 秒终止任务 | 正常/深层/权限异常样本各至少 10 次 |
| 超限扫描 | 超过配置上限明确失败并保留旧快照 | 边界前后各一个 fixture，不擅自提高既有上限 |
| 诊断 | 本地常规环境 P95 ≤ 5 秒 | 每项有超时；超时显示未知而非阻塞全界面 |
| 高频日志 | 总计 1,000 行/秒、每行约 200 字节、持续 10 分钟 | 检查停止按钮反馈 ≤ 1 秒，记录截断数量及内存曲线 |
| 日志内存 | 热身 2 分钟后最后一分钟与首个稳态分钟 RSS 中位数增幅 ≤ 20% | 同时记录绝对峰值；不满足则查队列/订阅泄漏 |
| 应用启动 | 同机同数据较 v0.1 中位耗时回退不超过 20% | 分别记录 10 次冷启动与 10 次热启动，不混算 |
| 进程与数据 | 测试受管进程零遗留、非受管进程零误杀、恢复关键数据一致 | PID/身份/端口与数据库证据交叉核对 |

网络盘、不可读目录等慢路径单独报告，不纳入普通本地磁盘目标后掩盖问题。

### 9.1 必须覆盖的端到端路径

1. 首次安装 → 导入 → 分析 → 诊断 → 确认方案 → 启动 → 查看地址/日志 → 停止 → 重开持久化。
2. 工作区新增项目 → 复扫差异 → 部分导入失败 → 重试 → 无重复记录。
3. 项目清单改变 → 过期提示 → 差异确认 → 保留人工配置 → 新授权启动。
4. 多方案切换 → 编辑运行中方案 → 当前进程不变 → 下一次启动采用新方案。
5. 端口冲突、缺命令、就绪超时 → 正确错误 → 历史日志定位。
6. 备份 → 从 v0.1 升级 → 数据校验 → 隔离恢复/失败保护演练。
7. 扫描、高频日志与退出并发 → 界面可操作 → 仅清理本次受管资源。

### 9.2 后续实施时的检查命令

现有入口：`pnpm.cmd typecheck`、`pnpm.cmd test`、`pnpm.cmd build`、`pnpm.cmd package:dir`、`pnpm.cmd verify:release`。安装器使用届时核对后的打包脚本；目前 `package` 指向 unsigned 路径，不能将其输出描述为已签名产物。

lint、Electron E2E、迁移 fixture 与性能采集入口如未建立，须在 V02-006 中补齐后登记真实命令。当前文档创建不执行这些命令，也不生成构建或测试产物。
