# V02-001 环境诊断与失败指引阶段验收报告

验收日期：2026-09-07。状态：在本文声明的支持范围内已完成阶段验收。范围为本地开发版的 V02-001，不代表整个 v0.2 已交付。需求依据：[开发规划第 4.1 节](./01-v0.2开发规划与验收方案.md)。历次增量见 [实施记录](./02-开发进度与环境诊断实施记录.md)，本报告描述最终行为，取代其中历史性的“剩余工作”状态。

## 1. 交付行为

项目详情提供“环境诊断”。用户可以先检查已保存方案，按服务查看问题，再进入依赖安装预览或运行历史。存在未保存配置时要求先保存；切换方案、修改配置或结果超过一分钟后，旧结果不能显示为当前有效结果。

自动诊断检查目录、明确文件引用、命令来源、显式必需变量、包管理器及锁文件类型、虚拟环境线索和端口。每项显示通过、警告、阻断、未确定或不适用，并提供原因和下一步建议。检查不读取 `.env` 内容，不运行项目脚本，不安装依赖。

用户可单独选择项目外的 Node、Python 或 Java 可执行文件，经原生确认后执行一次固定版本命令。支持的静态版本声明与服务命令进行匹配，无法确定的间接调用和复杂声明明确保留“未确定”。诊断结果不是执行授权，启动及安装仍需既有确认流程。

## 3. 首批支持矩阵

| --- | --- | --- |

| Java | 服务目录 POM 中受限的 Maven Enforcer `requireJavaVersion`，Java 9+ 整数范围边界 | 父 POM、profiles、配置合并、Gradle、wrapper、完整 Maven 范围及 Java 8 映射 |
| 包管理器 | 直接命令与本地 `packageManager` 的家族比较，当前目录锁文件家族冲突 | 包管理器版本、依赖完整性、父工作区声明及目录重定向参数对应的真实目标 |
| 环境变量 | 服务编辑器新增可选 `required`；显式必需且空白的值阻断 | 从源码或 `.env` 推断应用必需变量、判断凭据是否有效 |
| 文件参数 | 明确脚本首参及 `--config`、`--env-file`、`--require`、`-r`、`-jar` 文件路径 | 模块名解析、脚本内部引用；项目外引用显示未确定 |

Java 结果专门标为“构建 JVM”：没有证明 Maven 实际选用该 Java，也不等价于应用运行兼容性。因此 Java 声明不满足显示警告；有匹配版本证据的 Node/Python 声明不满足显示阻断。

以上未覆盖项是显式的支持边界，不是通过项。版本证据缺失或方案不匹配时保留未确定，用户仍可进入既有执行确认；未取得版本证据不等于应用保证版本兼容。Go、Rust 等不增加自动版本检查。

## 4. 版本证据和执行边界

1. 用户选择物理路径；只接受对应名称的 `.exe`，拒绝当前项目内部程序。选择与确认由主进程处理，renderer 不能提交任意执行路径或参数。
2. 使用 `node --version`、`python -I -S --version` 或 `java -version`，不使用 shell。在独立临时工作目录运行，清除 PATH 及非允许的环境变量。
3. 单次子进程超时为 3 秒，输出上限为 4 KiB。输出只用于受限版本解析，错误响应不包含原始输出。
4. 运行时文件上限 256 MiB，在确认及执行关键节点检查物理路径和 SHA-256。文件身份检查有协作取消；它不是操作系统级沙箱，也不宣称消除了所有文件系统竞态。
5. 静态清单读取限制为单文件 64 KiB、最多 32 个启用服务，使用既有原生路径边界。基础读取具有候选数和协作时间预算；不同步骤有独立限时，不将其描述为整个请求严格在 5 秒内结束。
6. 内存版本证据最多 64 组，绑定方案、项目根目录与进程环境。有效期一分钟；同一绑定下已过期或运行时文件变化会要求重新检查。启动前重读当前声明及文件摘要，不自动再次执行版本命令。
7. 配置变化或应用重开后不沿用旧版本证据，回到未确定。单服务重启使用原会话的服务快照，不能把后来编辑的保存方案当成该进程配置；通常不匹配完整方案的版本证据，不宣称已完成版本复检。
8. 重启先停止原服务并释放其端口，再进行实时静态检查。若检查失败，不创建替代进程，历史保留原服务已停止的事实和失败说明；停止/退出与检查并发时不再生成新进程。

## 5. 异常验收矩阵

| 场景 | 结果 | 证据表面 |
| --- | --- | --- |
| 正常运行环境 | 受控服务启动、停止、重启成功 | 真实 Electron 与进程生命周期 |
| 缺少运行时或命令 | 定位具体服务并阻断，不弹出可执行确认 | 诊断/预检测试、Electron |
| 版本声明不满足 | Node/Python 比较结果不满足；Java 显示构建 JVM 范围；不支持声明显示未确定 | 真实 Node、Python 3.13.0、JDK 21.0.5，语法边界测试 |
| 检查后清单或程序发生变化 | 重读清单；运行时摘要变化或证据过期要求重查 | Electron 修改 Node 声明；版本证据单元测试 |
| 多锁文件冲突 | 警告而非依赖已完整 | 服务输入诊断测试 |
| 虚拟环境失效 | 缺少解释器警告；存在解释器仍不证明依赖完整 | 真实隔离目录测试 |
| 必需变量缺失 | UI 保存必需标记，空值阻断；诊断不显示键名和值 | Electron 编辑流程、秘密变量保存与诊断测试 |
| 端口检查后被抢占 | 再检查阻断，外部占用进程不受影响 | 真实 Electron 和本地 TCP 服务 |
| 版本命令超时 | 超时结束检查，无项目会话，无原始输出泄露 | .NET 编译的受控超时程序、真实 Electron |
| 重启时文件已删除 | 无替代进程，保留两条服务历史及处理建议 | 真实 Electron、历史展开截图 |
| 就绪超时和提前退出 | 保留退出/就绪原因，不把失败标为就绪；提供不同建议 | 真实进程的编排/恢复集成测试、建议映射测试 |
| 安装后仍缺运行条件 | 拒绝启动；安装预览取消不产生会话 | 处理器测试和 Electron 预览取消 |

## 6. 检查命令和证据限制

- `pnpm.cmd build`：通过；最后的历史入口修改后再次执行桌面 `vite build` 通过。
- `pnpm.cmd typecheck`、`pnpm.cmd lint`：通过，包含 E2E 返回契约检查。
- `pnpm.cmd test`：56 个文件、603 项通过。
- `pnpm.cmd test:e2e:built`：8 项通过，28.3 秒，0 跳过；本轮配置三个本机工具变量。最终截图核对见实施记录第 10 节。
- `git diff --check`：用于检查已跟踪修改格式，不代替新增文件的类型、lint 和运行检查。

复现完整桌面测试需设置 `CODEHELM_E2E_PYTHON`、`CODEHELM_E2E_JAVA` 和 `CODEHELM_E2E_CSC` 为本机可信程序路径；路径不写死在测试源码中。未配置时相应三项会明确跳过，不得记作八项完整通过。超时程序在隔离临时目录生成，测试后清理。

Electron 使用构建产物和独立临时 userData/项目夹具。原生运行时文件选择和确认框的返回值由测试替身提供，真实子进程、静态读取和 Vue 界面执行；不把此结果当作系统对话框人工验收。安装预览使用实际应用确认窗口，未执行网络依赖安装。安装后的控制流由测试覆盖，不宣称真实包下载已验证。

既有原生 C++ 编译标准覆盖警告、前端大 chunk 警告仍存在。此阶段没有生成发布安装包，没有做干净虚拟机安装或升级回滚验收，这些属于 V02-006。没有改变 v0.1 独立门禁或正式用户数据库。
