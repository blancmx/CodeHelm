# Windows 隔离安装、升级与回退验收清单

> V02-006 执行材料；未勾选项不代表通过。
> 必须在可重置虚拟机或独立测试机执行，不在正式使用的 CodeHelm 数据目录演练。

## 1. 验收前准备

- [ ] 记录 Windows 版本、构建号、架构、CPU、内存、磁盘类型与空闲空间。
- [ ] 创建虚拟机快照，确认本机没有必须保留的 CodeHelm 数据或受管项目进程。
- [ ] 将候选安装器、其 SHA-256 清单和已有 v0.1.0 安装器复制到测试机，逐个核对摘要。
- [ ] 使用普通用户账户。测试目录至少覆盖中文和空格，例如 `C:\CodeHelm 验收\安装目录`。
- [ ] 准备独立 Node/Python/Java 项目 fixture；另建未安装开发运行时的快照，以区分应用启动与项目运行前提。
- [x] 冻结候选版本 `0.2.0-rc.1` 并生成安装器，见 [构建及摘要记录](./12-rc.1候选构建与载荷验收.md)。此项只表示候选准备完成；真正安装升级仍需执行下表，不将旧的 `0.1.0` 同版本包作为升级证据。

默认数据目录为 `%APPDATA%\CodeHelm`。测试机中可使用默认目录验证真实产品流程；自动化业务回归使用 `CODEHELM_USER_DATA_DIR` 指向临时目录。两类证据分别记录。

## 3. 已有自动化可复用入口

在有开发工具的独立测试机，安装后的二进制也可以运行同一业务套件：

```powershell
$env:CODEHELM_E2E_EXECUTABLE = 'C:\CodeHelm 验收\安装目录\CodeHelm.exe'
$env:CODEHELM_E2E_PYTHON = (Get-Command python.exe).Source
$env:CODEHELM_E2E_JAVA = 'C:\实际 JDK 目录\bin\java.exe'
$env:CODEHELM_E2E_CSC = "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe"
pnpm.cmd test:e2e:built
```

自动化会创建和清理自己的临时用户目录；不会验证默认 `%APPDATA%\CodeHelm` 的安装器迁移行为，因此仍需单独执行上表。恢复系统确认框在自动化中模拟返回值，原生框的可见性、默认取消和键盘操作需人工核验。

10 分钟持续日志压力测试显式启用：

```powershell
$env:CODEHELM_E2E_PERFORMANCE = '1'
pnpm.cmd test:e2e:built --grep 'measures sustained'
```

这条命令会重新生成打包版测试结果文件。归档完整回归结果后再做定向复测，避免将单项报告误当成全量报告。

## 4. 发布前冻结

完成矩阵后，冻结准确的源码提交、依赖锁文件、构建工具链、最低支持 Windows 版本和 x64 架构。重新构建并对最终产物重复关键检查；本地未提交工作区产物不直接晋升为发布候选。

未经签名的安装器明确标为未签名测试候选；签名、公开上传和发布渠道在最终资产可审阅后另行授权。不能复用旧安装器摘要，也不能将目录包通过解释成全新安装、升级和回退已通过。
