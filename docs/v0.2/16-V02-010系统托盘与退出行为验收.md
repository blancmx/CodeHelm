## 功能范围

- 设置新增“关闭到托盘”，默认关闭；旧设置读取时自动补默认值，无需数据库结构迁移。
- 勾选并保存后，由主进程弹出启用确认。取消会保持关闭，其他设置仍可保存。再次关闭后重新启用会再次提示。
- 启用后，窗口关闭按钮和系统关闭事件只隐藏原窗口，已启动服务与日志订阅继续存在。
- 单击或双击托盘图标、菜单“显示窗口”、再次启动应用均恢复原窗口，不重新加载页面或创建新订阅。
- “查看运行状态”恢复窗口并进入现有运行中心，使用真实 Runner 状态；不自动启动或接管任何项目。
- “退出 CodeHelm”执行现有受管服务停止和数据库、日志清理流程。清理期间冻结新业务 IPC，重复退出请求不能绕过清理。
- 关闭托盘开关时先显示窗口，再销毁托盘。托盘图标缺失或初始化失败时不启用隐藏行为；启动恢复失败会明确提示本次仍关闭退出。

## 实现边界

- `TrayController` 管理唯一原生托盘对象，重复启用复用实例，退出统一销毁。菜单不提供任意命令执行入口。
- `closeToTray` 使用既有可信设置 IPC、严格 schema 校验和数据库存储。保存串行互斥，避免确认过程中并发修改。
- 页面使用现有设置样式；开关可通过键盘操作，并说明立即生效与显式退出入口。
- 退出沿用 Runner 的身份核验和停止逻辑，身份不匹配的进程不强制终止。既有 ORPHANED 记录与后续人工检查语义保持不变。
- 不增加开机自启动、自动运行项目、进程接管或托盘远程控制接口。

- 默认 GPU 的首次全量运行有 2 项截图超时：历史失败日志及高吞吐日志用例均已完成业务断言，在 `page.screenshot` 阶段超时。保留 `test-results/v02-010-dev-attempt1-results.json` 和对应 artifacts。软件渲染复核全量通过；最终默认 GPU 托盘专项也通过，未改变应用默认渲染设置。
