# V02-008 运行配置模板与导入导出

日期：2026-09-12。

## 范围与入口

本阶段按 v0.2 规划实现本机项目之间的运行配置复用。项目详情的运行方案工具栏新增“导入 / 导出模板”；存在未保存修改时不可进入，避免导出内容与正在编辑的内容混淆。

支持当前方案导出、读取 JSON 文件、粘贴 JSON、Node 通用模板、占位变量填写、差异预览、确认后另存为新方案。模板本身是可保存、复制和再次导入的本地 JSON 文件，无需额外模板数据库。在线模板市场和跨机器秘密迁移不在此阶段范围内。

## 文件格式及脱敏

文件采用 `format: "codehelm.run-profile"`、`version: 1`。保留方案名称、失败策略、服务类型、相对目录、端口、就绪检查结构、依赖关系、启用状态和环境变量名称。主进程执行严格格式校验，拒绝未知字段、未知版本和超过 256 KiB 的 UTF-8 输入。

导出重新生成局部服务标识，剔除项目/方案 ID、创建时间、确认时间、来源、历史与授权信息。不导出描述，防止自由文本携带本机信息。

参数和环境变量可能包含未标记的令牌，因此默认将**所有参数值和环境变量值**替换为显式占位符；就绪检查中的 HTTP 路径、日志正则和端口提取正则同样替换。非裸命令名的可执行文件也替换为占位符。模块目录和工作目录必须已经是有效的项目内相对路径，否则拒绝导出并要求先修正配置。

示例占位符：`{{SERVICE_1_ARG_1}}`、`{{SERVICE_1_ENV_1}}`。占位符必须占据整个字段，不做脚本插值或表达式计算。通用 Node 模板使用 `{{ENTRY_FILE}}`。导出再导入的结构等价验收需显式补回这些值；脱敏 JSON 不支持免填写迁移秘密。

“保存脱敏 JSON 文件”调用 Electron 原生另存为，主进程从已保存方案重新生成脱敏内容，写入用户选择的路径。取消选择不产生文件。用户自行添加到方案名、服务名和变量名中的内容仍会按元数据保留，分享前应核对这些名称。

## 导入与确认

1. 读取文件、粘贴 JSON，或选用 Node 通用模板。
2. “校验模板”检查格式、大小、目录、服务标识、依赖存在性、启用关系和循环依赖，列出需要填写的变量。
3. 填写新方案名称及全部占位变量。缺失值或嵌套占位符阻断预览与保存，因此不能带着未填模板启动。
4. 主进程重新验证变量替换后的可执行文件和参数路径；只允许项目内相对路径，拒绝绝对路径和上级目录。工作目录与模块目录须真实存在，目录链接不得越出项目根目录；含目录段的相对可执行文件也须存在且位于项目内。
5. 预览显示目标项目、已有方案数量、新增服务、参数模板、就绪检查类型、目录、依赖及变量名称；变量输入使用可切换显示的密码输入框，预览不回显填写的值。修改 JSON、名称或变量会清空旧预览。
6. 勾选确认后保存为新方案，同名方案拒绝导入，不覆盖已有方案。方案与服务使用新的 UUID，依赖重新映射，默认状态不改变已有默认方案，执行确认时间为空。

预览在主进程保留，绑定发起窗口，五分钟有效，一次使用；每个窗口至多一个待确认预览，全局最多 20 个。确认前重新检查项目路径、根目录身份、配置目录与名称冲突。秘密环境变量按现有本机加密机制保存，返回渲染端时脱敏。模板操作不调用安装器、分析脚本或 runner；首次执行继续经过既有执行确认通道。
