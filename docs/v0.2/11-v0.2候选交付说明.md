## 已验证的使用边界

- 静态诊断不执行项目脚本、不安装依赖，不证明依赖完整或项目一定能启动。版本检查须单独确认，也不授权项目启动。
- Java 只比较支持的本地 Maven Enforcer 构建 JVM 声明；支持四段稳定数字版本。父 POM、条件配置、间接命令和未支持的版本语法保守返回未确定。
- 扫描默认文件预算为 50,000；超限明确失败并保留原记录。正常、深层、权限异常及极限负载的取消均有独立样本。
- 日志界面和查询均有界；导出的是已加载的筛选结果，不承诺完整会话日志无条件导出。
- 备份对象是应用管理数据，不是工程源码、项目依赖或外部数据库。恢复后新增于备份时间点之后的数据可能丢失，必须核对所选备份及恢复前保全。
- 保留执行确认、文件边界和受管进程身份核验；验收脚本使用临时数据，未操作正式 `%APPDATA%\CodeHelm`。

## 后续验收顺序

2026-09-14 更新：V02-007～011 已纳入当前源码。下列历史 CI 与旧安装器保留原有证据含义，当前提交的统一验证与剩余门禁见 [发布收口记录](./18-v0.2发布收口与当前提交验收.md)。不将旧安装器视为包含这些新增功能的最终资产。

按用户要求，先完成可在当前环境及 CI 进行的验收，再安排隔离 Windows 环境。后置不等于免验。

1. 最新测试提交的 CI 已核验并保存报告；后续源码变更需重新核验，历史失败及重试信息保留。
2. 候选版本已选定为 `0.2.0-rc.1`；冻结准确源码、支持系统和分发方式，重建用于安装验收的安装器与摘要。现有 `0.1.0` 同版本包不能作为真实 `0.1 → 0.2` 安装器升级证据。候选保持未签名内测用途，公开发布未授权。
3. 在可重置环境执行 [安装、升级、回退及无开发工具矩阵](./09-Windows隔离安装升级验收清单.md)，补齐真实慢盘/网络盘及冷启动对照。
4. 核对最终资产与被测资产一致；全部发布门禁关闭后，再办理公开发布授权。

目前不得将整个 V02-006 或 v0.2 标为发布完成，也不把目录包通过、schema fixture 迁移或热启动对照替代真实安装、升级、回退或冷启动证据。
